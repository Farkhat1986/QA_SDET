## Часть 2. Тестирование API

### Bug Report 1: Несоответствие документации кодам ошибок

```commandline
**Title:** PUT /v1/disk/resources возвращает 409 вместо 400 при создании существующей папки

**Description:** 
При попытке создания папки по уже существующему пути API возвращает статус 409 Conflict вместо заявленного в требованиях 400 Bad Request

**Steps to Reproduce:**
1. Вызвать PUT https://cloud-api.yandex.net:443/v1/disk/resources с валидным токеном
2. Указать path=/test_folder
3. После успешного создания (200) повторить тот же запрос с тем же path

**Expected Result:**
Статус ответа: 400 Bad Request
Тело ответа содержит описание ошибки

**Actual Result:**
Статус ответа: 409 Conflict
Тело ответа: {"message":"Ресурс уже существует","error":"DiskPathDoesntExistsError"}

**Environment:**
- API: Яндекс.Диск REST API v1
- Метод: PUT /v1/disk/resources
- Заголовки: Content-Type: application/json, Authorization: [valid_token]

**Severity:** Medium
**Priority:** Medium
```

### Bug Report 2: Отсутствие валидации параметра path

```commandline
**Title:** PUT /v1/disk/resources принимает некорректные пути без валидации

**Description:** 
API позволяет создавать папки с некорректными путями, содержащими запрещенные символы

**Steps to Reproduce:**
1. Вызвать PUT https://cloud-api.yandex.net:443/v1/disk/resources
2. Указать path=/folder*with*invalid*chars?test=1
3. Отправить запрос

**Expected Result:**
Статус ответа: 400 Bad Request с описанием невалидного пути

**Actual Result:**
Статус ответа: 201 Created или 200 OK (папка создается с некорректным именем)

**Environment:**
- API: Яндекс.Диск REST API v1
- Метод: PUT /v1/disk/resources

**Severity:** High
**Priority:** High
```

### Bug Report 4: Отсутствие таймаута выполнения запроса

```commandline
**Title:** PUT /v1/disk/resources не имеет таймаута выполнения при создании папок

**Description:** 
API не ограничивает время выполнения операции создания папки, что может привести к зависанию клиентских приложений

**Steps to Reproduce:**
1. Имитировать медленное сетевое соединение или высокую нагрузку на сервер
2. Вызвать PUT https://cloud-api.yandex.net:443/v1/disk/resources
3. Наблюдать за временем выполнения запроса

**Expected Result:**
Запрос должен завершаться с таймаутом (например, 30 секунд) с соответствующим кодом ошибки 408 или 503

**Actual Result:**
Запрос может выполняться неограниченно долго без ответа

**Environment:**
- API: Яндекс.Диск REST API v1
- Метод: PUT /v1/disk/resources

**Severity:** High
**Priority:** Medium
```

### Bug Report 5: Отсутствие пагинации в ответах поиска

```commandline
**Title:** Поиск по файлам не поддерживает пагинацию при большом количестве результатов

**Description:** 
При поиске, возвращающем большое количество файлов, отсутствует механизм пагинации, что приводит к передаче огромных объемов данных

**Steps to Reproduce:**
1. Иметь на Диске 1000+ файлов, удовлетворяющих одному поисковому запросу
2. Выполнить поиск по общему критерию
3. Наблюдать за ответом

**Expected Result:**
Ответ должен содержать пагинацию:
- limit - количество результатов на странице
- offset - смещение
- total - общее количество результатов
- links - ссылки на следующую/предыдущую страницы

**Actual Result:**
Все результаты возвращаются одним списком без разбивки на страницы

**Environment:**
- UI: Поиск Яндекс.Диска
- API: (предположительно) GET /v1/disk/resources/search

**Severity:** Medium
**Priority:** Medium
```

### Bug Report 6: Необработанная ошибка таймаута

```commandline
**Title:** При таймауте запроса клиент получает неинформативную ошибку

**Description:** 
При превышении времени выполнения запроса клиент получает generic error вместо понятного сообщения о таймауте

**Steps to Reproduce:**
1. Настроить сервер на искусственную задержку ответа > 30 сек
2. Вызвать любой метод API (например, создание папки)
3. Дождаться таймаута

**Expected Result:**
{
  "message": "Request timeout",
  "description": "Сервер не ответил в течение установленного времени",
  "error": "TimeoutError",
  "retry_after": 30
}

**Actual Result:**
Соединение разрывается без тела ответа или возвращается:
{
  "message": "Internal Server Error",
  "error": "ServerError"
}

**Environment:**
- API: Яндекс.Диск REST API v1
- Любой метод

**Severity:** Medium
**Priority:** Medium
```

### Bug Report 7: Отсутствие лимитов на частоту запросов

```commandline
**Title:** API не ограничивает rate limiting, что позволяет DoS-атаки

**Description:** 
Отсутствует ограничение на количество запросов в единицу времени, что делает API уязвимым для злоупотреблений

**Steps to Reproduce:**
1. Написать скрипт, отправляющий 100+ запросов/секунду на создание папок
2. Запустить скрипт
3. Наблюдать за ответами сервера

**Expected Result:**
После превышения лимита (например, 60 запросов/минуту) должен возвращаться:
Status: 429 Too Many Requests
Headers: Retry-After: 60
Body: {"message": "Too many requests", "description": "Превышен лимит запросов"}

**Actual Result:**
Все запросы обрабатываются без ограничений

**Environment:**
- API: Яндекс.Диск REST API v1

**Severity:** High
**Priority:** High
```

## Дополнительные тест-кейсы для API:
#### 1. Создание папки с пустым path должен быть 400

#### 2. Создание папки без заголовка Authorization должен быть 401

#### 3. Создание папки с невалидным Content-Type должен быть 400, 415

#### 4. Создание вложенной папки в несуществующей родительской должен быть 409, 404

#### 5. Проверка поля fields - запрос разных комбинаций возвращаемых атрибутов
