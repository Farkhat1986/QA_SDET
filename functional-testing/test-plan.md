# План тестирования REST API: GET /products/{productId}/cost
## 1. Введение

### Цель: 
* #### Проверить корректность, надежность и безопасность работы эндпоинта расчета стоимости продукта

### Объект тестирования: 
* #### REST API метод GET /products/{productId}/cost?authToken=&count=&start=

### Методология: 
* #### Позитивное тестирование
* #### Негативное тестирование и обработка ошибок
* #### Граничное тестирование
* #### Тестирование безопасности 
* #### Производительность и нагрузочное тестирование

## 2. Тестовое окружение

### Сервер/Стенд: 
* #### URL тестового окружения (пример, https://test-rest-api.example.com)

### Тестовые данные:

* #### Валидный productId: Например, 123
* #### Heвалидный productId: Например, 99999 (несуществующий) или "abc" (некорректный тип)
* #### Валидный authToken: Cтрока из 16 символов (буквы и цифры), пример A1b2C3d4E5f6G7h8
* #### Невалидный authToken: Cтрока не соответствующая требованиям (меньше 16 символов, не те символы, пустая, больше 16 символов)
* #### Отсутствующий authToken: Параметр не передается в запросе

### Инструменты:

* #### REST-клиент: 
  * ##### Postman, Insomnia

* #### Автоматизация (опционально): 
  * ##### Python (requests + pytest)

* #### Нагрузочное тестирование (опционально): 
  * ##### Locust (Python), возможно аналоги

### 3.2 Негативное тестирование и обработка ошибок

| **ID** | **Название / Цель**                                       | **Параметры**                 | **Ожидаемый результат (Response Body)**               | **Ожидаемый HTTP-код** |
|--------| --------------------------------------------------------- |-------------------------------| ----------------------------------------------------- | ---------------------- |
| N1    | Невалидный authToken                                      | authToken=no_A1b2C3d4E5f6G7h8 | {"errorMessage": "Unauthorized"} или пустое тело      | 401                    |
| N2    | Отсутствует authToken                                     | Параметр authToken не передан | {"errorMessage": "Unauthorized"} или пустое тело      | 401                    |
| N3    | Несуществующий productId                                  | productId=99999               | Пустое тело или {"errorMessage": "Product not found"} | 404                    |
| N4    | Некорректный тип productId                                | productId=abc                 | {"errorMessage": "Invalid productId format"}          | 400 или 500            |
| N5    | Параметр count отсутствует                                | Параметр count не передан     | {"errorMessage": "Missing required parameter: count"} | 400                    |
| N6    | Параметр start отсутствует                                | Параметр start не передан     | {"errorMessage": "Missing required parameter: start"} | 400                    |
| N7   | Некорректный тип count (не число)                         | count=abc                     | {"errorMessage": "Invalid parameter format"}          | 400                    |
| N8   | Некорректный тип start (не число)                         | start=xyz                     | {"errorMessage": "Invalid parameter format"}          | 400                    |
| N9   | Отрицательное значение count                              | count=-1                      | {"errorMessage": "Parameters must be non-negative"}   | 400                    |
| N10   | Отрицательное значение start                              | start=-5                      | {"errorMessage": "Parameters must be non-negative"}   | 400                    |
| N11   | Нулевое значение count                                    | count=0                       | {"cost": 0}                                           | 200                    |
| N12   | Очень большое значение count                              | count=1000000                 | {"errorMessage": "Count is too large"}                | 400 или 500            |
| N13   | start выходит за пределы первой партии (start=5, count=1) | start=5, count=1              | Расчет для следующей партии: {"cost": 30}             | 200                    |

### 3.4 Тестирование безопасности

| **ID** | **Название / Цель**                              | **Параметры / Действия**                                        | **Ожидаемый результат**                                                              |
| ------ | ------------------------------------------------ |-----------------------------------------------------------------|--------------------------------------------------------------------------------------|
| S1   | SQL-инъекция в productId                         | productId=1' OR '1'='1                                          | 404 или 400 Не должно быть данных об ошибках СУБД                                    |
| S2   | Проверка длины и формата authToken               | authToken=123 (короткий), authToken=1234567890abcdef1 (длинный) | 401                                                                                  |
| S3   | Проверка чувствительности к регистру в authToken | authToken=AbCdEf1234567890 или authToken=abcdef1234567890       | Должно либо учитывать регистр, либо нет                                              |
| S4   | Попытка перебора authToken         | Множество запросов с разными невалидными токенами               | После определенного количества попыток должен следовать бан IP или введение задержки |


### 3.5 Производительность и Нагрузочное тестирование (опционально)

| **ID**  | **Название / Цель**                  | **Сценарий**                                           | **Критерии успеха**            |
| ------- | ------------------------------------ |--------------------------------------------------------|--------------------------------|
| PERF1 | Время отклика для одного запроса     | 1 пользователь, 1 запрос с валидными данными           | Среднее время отклика меньше 500 мс |
| PERF2 | Нагрузка в течение короткого периода | от 10 до 50 concurrent пользователей в течение 5 минут | Частота ошибок меньше 1%       |


### 4. Критерии приемки:

* #### Все тесты из разделов Позитивное тестирование и Граничное тестирование проходят успешно

* #### Все тесты из раздела Негативное тестирование возвращают ожидаемые коды ошибок и сообщения

* #### Проведена проверка безопасности (S1, S2), система устойчива к базовым атакам

* #### (Опционально) Выполнены критерии производительности

### 5. Отчетность:

* #### Дефект: 
  - Каждый проваленный тест-кейс должен быть заведен как дефект в баг-трекинговой системе. В дефекте должны быть указаны: 
    * #### Шаги для воспроизведения
    * #### Фактический результат
    * #### Ожидаемый результат
    * #### Серьезность (Severity) и приоритет (Priority)
    * #### Логи/скриншоты

* #### Тестовый отчет: 
  - По итогам тестирования формируется отчет, включающий: 
    * #### Общую статистику (сколько пройдено, сколько не пройдено, сколько блокировано)
    * #### Список критичных найденных дефектов
    * #### Рекомендации к выпуску версии (Ready/Not Ready)
